# 2.9.0-dev.12 — 피드백 셸 (toast · confirm)

브랜치: `feat/feedback-shell` — `001c68a` 통합선 머지. `/` `toast.js`·`feedback.js` 셸 parity로 toast(alert/success)와 confirm 게이트를 `/edit`에 올린다. toast는 상단 중앙·2000ms 자동 소멸·클릭 dismiss·타입별 색상, confirm은 예/아니오 버튼·`bgDismiss`·닫힘 시 에딧창 포커스 복원. (`/` parity, UX 변경 없음)

`VERSION` / tag는 **React 완전 변환 완료 시** `2.9.0`으로만 반영한다.

### Decision

- **sonner (채택) vs 자체 toast DOM 이식 (기각)** — shadcn 계열 Radix 기반 셸. queue·dismiss·타입 색상·중복 toast가 셸 parity의 기본 조건. 자체 구현은 queue/dismiss 비용. 신규 의존성(`sonner` ^2.0.8)은 사용자 확인 게이트.
- **confirm 셸 vs alert 창 (기각)** — 예/아니오·콜백(success/cancel)·`bgDismiss` 게이트가 confirm UI의 기본. alert 창으로는 게이트·콜백 표현 불가.
- **포커스 복원 prevFocusRef (채택) vs 복원 없음 (기각)** — confirm 진입 시 `document.activeElement`(에딧창) 저장 → `onCloseAutoFocus` preventDefault 후 focus.
- **confirm vs dialog-shell 통합 기각 (현행 유지, 리뷰 D4)** — confirm은 예/아니오·bgDismiss·content `<br/>` 인라인 HTML로 셸 역할이 dialog-shell과 다름.
