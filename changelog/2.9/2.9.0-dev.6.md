# 2.9.0-dev.6 — 시트 undo/redo (실행취소·재실행)

브랜치: `feat/edit-sheet-undo` — `/edit` React 시트에 **undo/redo**(탭별 비영속 스택)·**Ctrl+Z/Y·Ctrl+Shift+Z**·**toolbar 실행취소/재실행 버튼**·**push/clear 지점**을 이관한다. (`/` `utils/editHistory.js`·`sheet/history.js`·`sheet/mutate/command.js` parity)

`VERSION` / tag는 **React 완전 변환 완료 시** `2.9.0`으로만 반영한다.

### Decision

- **스택 연산은 feature 순수 함수** — `edit-history`(pushEntry truncate·prevEntry/nextEntry 선소비·canUndo/canRedo·탭 CRUD 스택 동기화). apply 분기(insert/remove/update/multi.*)는 `apply-history-entry`. widget은 push 조립 + `applyFocus` 연결만 (`use-sheet-undo-actions`)
- **비영속 스토어** — `useSheetHistoryStore`는 `create()`(persist 없음). `useSheetStore` persist에 스택 미포함. 검색 스토어(`sheet-search`)와 분리
- **U1 선소비 parity** — `prevEntry`/`nextEntry`가 스택을 먼저 소비하고, apply 가드(`timelineSnapshotEquals`·multi patch snapshot) 실패해도 스택은 소비된다
- **U5 단일 행 삭제** — `lastIndex===0`이면 `remove`가 아닌 `update(EMPTY_TIMELINE)` entry로 행 유지
- **M5 undo 전용 제거 경로** — `removeActiveTimelineAtForHistory`(entities)는 `multipleActive` 게이트가 없다. insert undo·remove redo가 다중 선택 중에도 스택·데이터가 함께 이동한다
- **M2 selection parity** — `/` `history.js`의 undo는 선택 상태를 건드리지 않는다. `spliceActiveTimelineAt`·undo 전용 제거는 `selectedRows`를 클리어하지 않는다
- **H1 preventDefault 타이밍** — 엔진이 핸들러 전에 `preventDefault`를 걸면 contenteditable 네이티브 undo까지 죽는다. 옵션에 두지 않고 가드 통과 후 핸들러 안에서 호출한다
- **M3 redo 키** — `ctrl+y` + `ctrl+shift+z` 병행 (mask comma → 엔진이 두 mask 등록)
- **pending focus 공유 추출** — `use-pending-focus`(rows·totalHeight 가드 후 `applyFocus`)를 selection·undo가 공유. 포커스 커서는 `resolve-focus-cursor`

### Notes

- 스택은 세션 전용 — 새로고침·localStorage에 히스토리는 남지 않는다. 시트 데이터는 persist와 동일
- undo/redo는 shortkey registrar만 사용 (시트 widget 전역 keydown 없음). 에딧 중·설정 input·검색 input 중 키 미발화
- `multi.*` 패치는 인덱스 기반 — 실행 후 행 CRUD로 인덱스가 어긋나면 snapshot 가드가 적용을 막는다 (U1: 스택은 소비)
- macOS Cmd는 엔진이 `ctrlKey`만 본다 (엔진 한계, 현 작업 범위 밖)
